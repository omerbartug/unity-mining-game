# Project Instructions

## General
- Do not modify files unless explicitly asked.
- Before implementing a non-trivial change, explain the proposed approach.
- Prefer simple solutions over unnecessary abstractions.
- Preserve existing behavior unless the task explicitly requires changing it.
- Do not introduce dependencies without explaining why they are needed.

## Code Quality
- Keep responsibilities separated.
- Avoid unnecessary managers and singleton dependencies.
- Prefer clear names over clever abstractions.
- Do not duplicate state unnecessarily.

## Workflow
1. Understand the relevant existing code.
2. Explain the root cause.
3. Propose a solution.
4. Wait for approval for architectural changes.
5. Implement.
6. Run tests/build.
7. Explain what changed and why.

## Learning
I am a computer engineering student.
When implementing something non-trivial, explain:
- why the solution works
- important trade-offs
- possible failure cases
- what I should understand from the implementation
